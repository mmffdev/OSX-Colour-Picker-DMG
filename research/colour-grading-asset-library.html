Colour Grading Asset Library

One searchable catalogue for looks, transforms, references and colour-pipeline dependencies across DaVinci Resolve, Adobe Premiere and Final Cut Pro—while the original files stay where their applications expect them.

The opportunity

A colourist collects reusable looks, technical transforms, reference images and the settings needed to reproduce an approved result. Colorgain could manage those relationships across applications, projects, folders and disks.

A creative look, a camera conversion and a display calibration can all involve LUTs, but they serve different purposes. The library should make that purpose explicit. Colour grading changes an image’s appearance; profiling characterises a device. A file extension alone does not establish either purpose.

The proposed value is answering: Which look is this, what does it expect, where is the original, and what do I need to reproduce it?

What the applications give us

DaVinci Resolve

  • LUT exports: reusable colour transforms including .cube. Blackmagic’s published beginner training documents Generate LUT and 17-, 33- and 65-point cube options. That cited training is for Resolve 17; exact UI and format support should be checked against the installed version when building an adapter. [2]
  • Gallery stills with grades: Blackmagic’s Resolve 20 Colorist Guide documents a .dpx reference image paired with a .drx containing node-tree and grading data. Both files are needed for the documented still-grade interchange workflow and should be treated as one logical asset. [3]
  • Project exports: .drp files contain project settings, organisation and timelines, but not the source media itself. They belong to project archiving rather than being treated as portable looks. [4]
  • Rendered images and movies: useful as visual references or deliverables, but a rendered result is not the editable grade or a complete description of its colour pipeline.

Adobe Premiere

Premiere exports .cube LUTs from Lumetri. It also provides dedicated custom LUT folders, making those folders natural candidates for a Colorgain Appbridge connection. [5] [6]

Adobe documents user locations under ~/Library/Application Support/Adobe/Common/LUTs/, including Input, Creative and Technical roles. The adapter must preserve those roles rather than treating every LUT as interchangeable. App-specific presets could be catalogued separately, with rendering support evaluated per format and app version.

Final Cut Pro

Final Cut Pro imports .cube and .mga camera LUTs and saves colour corrections as effects presets. Apple notes that custom camera LUTs must be transferred separately when sharing a library—an immediate example of the dependency problem Colorgain could solve. [7] [8]

Apple documents custom camera LUTs under ~/Library/Application Support/ProApps/Camera LUTs/ and effects presets under ~/Library/Application Support/ProApps/Effects Presets/. Its sharing guidance uses Reveal in Finder and compressed copies of preset files. [9]

Portable transforms versus editable grades

A LUT cannot retain a whole editable grade: masks, tracking, spatial effects and time-dependent adjustments need a native representation. Colorgain can catalogue native assets without claiming it can reproduce every effect. Native grade rendering would require a supported integration or an externally rendered reference; a thumbnail is not proof of full compatibility.

A linked repository, with originals in place

Extend the existing file-handler spine with linked colour assets. The catalogue holds identity, metadata, relationships and cached previews; source files remain in their application or studio folders.

  1. Connect an existing folder. The user chooses application LUT folders, a shared studio library or project asset folders. Persist granted access using the existing folder-access/bookmark mechanisms, including the App Store sandbox.
  2. Identify content as well as location. Use stable catalogue IDs and content hashes to recognise identical copies, distinguish versions and detect changes. One logical asset may have several installed locations.
  3. Keep dependencies together logically. Link the Resolve still/grade pair, or an OCIO configuration and its referenced LUTs. Leave live application databases under their application’s control; prefer supported exports and documented interfaces.
  4. Preserve colour context. Record expected input gamut and encoding, output space/encoding, SDR/HDR context, pipeline position, relevant versions, author, licence and approval status. Unknown metadata stays visibly unknown; do not infer a trustworthy pipeline solely from a filename.
  5. Provide deliberate actions. Reveal Original, Preview, Locate Missing File, Export Package and Copy To Application Folder. Removing a catalogue entry leaves linked originals intact by default. Changes to originals or installed copies need explicit, reviewable operations.
  6. Reconcile against disk reality. Distinguish missing files, unavailable volumes, changed bytes and denied access. Retain recoverable records and offer Locate, Reconnect or Remove Link instead of silently deleting records or producing repeated alerts.

“Installed for Premiere” and “confirmed used in Project X” are different facts. Knowing actual project usage requires a supported project export, application integration or a user-declared association. Watching a LUT folder alone cannot establish usage.

Cached previews should be regenerated when source content or rendering conditions change. Backup and handover should preserve the original bytes, dependency relationships, provenance and redistribution restrictions.

What Colorgain could show

Choose one correctly interpreted reference image and compare several looks against the same image. The input interpretation and viewing transform must stay visible so a convincing thumbnail cannot conceal an incorrect pipeline.

Interpreted source→Technical conversion→Creative look→Output / viewing transform
  • Before/after and side-by-side look comparisons.
  • Waveform, RGB parade, vectorscope and clipping inspection.
  • Transformed palette colours and neutral ramps, retaining original masters.
  • Expected input/output, LUT dimensions and declared operating range where available.
  • Reference stills, approval notes and known missing dependencies for native presets.

Previewing a portable LUT and faithfully rendering a proprietary native grade are separate capabilities. Evaluate OpenColorIO for the former and application-specific adapters for the latter. Device calibration remains a separate workflow from creative look selection.

Complete recipes through ACES

ACES Metadata Files can describe an ordered colour pipeline and reference external look transforms. This offers a later route to managing complete recipes rather than disconnected LUT files. Preserve transform order, dependencies, version information and whether a transform has already been applied, so it is not applied twice. [10]

Recommended delivery stages

  1. Linked LUT library. Start with .cube, reference images, searchable metadata, duplicate/missing-file detection and trustworthy still-image previews. Keep originals in place.
  2. Grade and correction relationships. Add ASC CDL inspection/preview and Resolve grade/still pairing. Catalogue native app presets independently of any promise to render them.
  3. Pipeline dependency management. Add OCIO/ACES configurations, CLF/CTF transforms, AMF recipes and complete handover packages.

Questions to settle before implementation

  • Which input encodings, output spaces and viewing pipelines form the first supported preview set?
  • Which reference-image formats and bit depths will be supported initially?
  • Which application versions and folder roles can be verified through documented interfaces?
  • What can be previewed directly, what needs a companion still, and what remains catalogue-only?
  • Which assets may legally be redistributed in backups or team handovers?

Verification when built

  • Compare identity LUTs and known transforms against a reference engine with stated numerical tolerances; verify input/output encodings, range and processing order.
  • Compare the same reference frames in Colorgain and the originating application under documented matching viewing conditions.
  • Test duplicate names, duplicate bytes, changed files, disconnected drives, permission loss and relocation.
  • Test dependency packaging, Resolve still/grade pairing and restoration without overwriting originals.
  • Measure indexing, preview generation, scrolling and idle CPU/memory on large collections. Avoid continuous rescanning or redraw loops.
  • Validate sandbox folder access and cancellation/recovery in the Store edition.

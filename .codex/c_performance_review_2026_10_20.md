# Performance and production review — 20 October 2026

Scope: direct-download Studio app, current `colorgain-main` working tree. This was a read-only architecture/code audit with passive and scroll sampling of installed build 357; no source, catalogue, or installed app was changed. The worktree is not a release snapshot: at review time it had 105 modified, 9 deleted and 43 untracked paths. The installed binary passed 1,394 self-tests in 18.87 seconds, but that result does not verify every uncommitted source file. A five-second idle sample was mostly blocked in the event loop and did catch the one-second workspace-session timer. A 12-second scroll sample included `TileGrid.syncReviewControls`; it was dominated by idle time and accessibility sampling, so it is evidence of execution, not a latency benchmark. Physical footprint at sample time was about 552 MB, with a prior peak of 869 MB; this alone does not establish a leak.

## Findings in order of likely user impact

1. **P0 — Small edits perform a whole-catalogue transaction on the main call path.** `LibraryController.apply` calls `store.mutate` synchronously (`Controller.swift:182`). `LibraryStore.mutate` loads, saves, then loads again (`Model.swift:1321`). Load scans and decodes catalogue assets (`CatalogueTree.swift:452-457`); save scans the tree and serializes each palette (`CatalogueTree.swift:629-637, 805-850`). `Handler_File_Manager.writeWithAccess` canonicalizes, parses, reads and compares each destination under `NSFileCoordinator` (`FileHandlers/Handler_File_Manager.swift:79-130`). Skipping equal writes protects data but does not remove the scanning and serialization work. `Controller.apply` posts a library-change notification even if the mutation is a no-op (`Controller.swift:233-240`). Keep identity, coordination, transactions and external-change detection; introduce a measured fast path for one-asset changes, a dirty-ID set, and a catalogue revision check. Do not optimize this by dropping provenance or recovery checks. Add a fixture that times one rename/rating/tag edit as the library grows.

2. **P0 — The page-refresh contract fans out to unrelated subsystems.** A library notification calls `StudioFrame.reload` (`StudioWindow.swift:1500,1969`), which rebuilds library rail, context rail, collections, page, history and footer. `fillPage` invalidates all print previews, rebuilds bars from every palette, creates every tile, resets the grid, configures metadata/import controls, reloads the filmstrip and refreshes analysis (`StudioWindow.swift:2807-2907,3134-3164`). Search calls `fillPage` on each edit (`StudioWindow.swift:1173`); format and channel changes do likewise (`StudioWindow.swift:987,1367`). The grid's `items` setter then clears review controls, text caches and print previews (`UIPrimitives/ViewportGrid.swift:178-185`). Split updates into model revision, route data, presentation settings, and visible-card repaint. Search should debounce data filtering and avoid resetting the grid if the resulting identities are unchanged. A format-row toggle should update only visible value rows and geometry; it should not reload the library tree, metadata, print predictions or analysis.

3. **P1 — Settings still eagerly format and measure every swatch card.** The recent `cardTextCache` avoids repeating conversions for the same key, but `refreshCardSettings` maps every item across every selected format and measures every resulting string before repainting (`UIPrimitives/ViewportGrid.swift:54-80`). On a large palette, enabling P3, Adobe RGB or CIELAB therefore blocks the main thread before any visible card changes. Cache raw colour definitions by library revision; compute text for visible rows (plus a small prefetch margin) and use a stable column-width policy or an incrementally raised width. Keep cards at a stable width during interaction rather than measuring the entire dataset synchronously.

4. **P1 — Scroll/layout recomputes full palette lineage for controls that only need review state.** `TileGrid.syncReviewControls` runs on layout and every clip-view bounds change (`UIPrimitives/ViewportGrid.swift:89-135`). For each visible palette it calls a closure that linearly finds the palette and invokes `PaletteAssetHandler.presentation` (`StudioWindow.swift:1312`). `presentation` repeatedly scans all swatches for copy descendants, scans them again for projects, and filters colours (`PaletteAssetHandler.swift:101-117`); the review control uses only palette name, rating and flag (`UIPrimitives/PaletteAssetControls.swift:70-79`). Sidebar cells repeat this (`StudioWorkspace.swift:609`). Pass a lightweight `Swatch`/review snapshot and target boolean. Reserve full presentation for the one page where use count or colours are displayed. `PaletteAssetIcon` and `PaletteReviewControls` currently set `needsDisplay` on unchanged symbols/ink/review during each sync (`UIPrimitives/PaletteAssetControls.swift:4-6,53,72-79`); make setters idempotent.

5. **P1 — Thumbnail completion causes repeated complete page builds and unbounded image retention.** A photograph thumbnail completion stores an `NSImage` and calls `fillPage` (`StudioWindow.swift:581-597`). `fillPage` reconstructs all photo items and the whole grid. Intake batches likewise append decoded thumbnails and call `refreshIntakeImages`, which rebuilds/sorts the growing array and calls `fillPage` (`StudioWindow.swift:683-745`). The scan emits every 24 files (`StudioWorkspace.swift:1169-1200`), so a large folder repeatedly processes its growing prefix. `photoThumbnails` and `intakePreviews` have no byte/count budget (`StudioWindow.swift:550-559`). Keep thumbnail decoding off main as it is now, but coalesce completion notifications per display frame or short interval, update only affected cells, and use an `NSCache`/LRU with pixel-cost limits and file-version keys. Virtualize intake records; decode thumbnails for the viewport plus prefetch margin. Verify 1k and 10k-image folders and navigation cancellation.

6. **P1 — Output proof work occurs inside drawing and its cache is invalidated too broadly.** `TileGrid.draw` calls `onPrint` for uncached items (`UIPrimitives/ViewportGrid.swift:508-516`); that closure performs definition lookup and `Rendering.of` for every colour in the tile (`StudioWindow.swift:1320-1332`). `fillPage` clears the cache even for search, sort and format changes (`StudioWindow.swift:2842`), and `items.didSet` clears it again. Build predictions keyed by colour-definition revision plus output channel/profile/intent/tolerance as appropriate, run conversion outside `draw`, and repaint cards when results arrive. A source-only sort must not invalidate predictions.

7. **P1 — Sync can add a second complete read/merge after every edit on the UI thread.** `Controller.apply` calls `sync()` after saving (`Controller.swift:233-240`). If configured, `sync` calls `engine.check()` synchronously (`Controller.swift:1636-1653`); `SyncEngine.check` loads the catalogue again, reads remote JSON, merges and compares full libraries (`Sync.swift:721-736`). This is an additional bottleneck for synced users. Move check/merge planning to a serial worker with an immutable revision snapshot; commit on main only after revalidating the local revision. Preserve the existing conflict prompt, backups and transaction guards.

8. **P2 — Repeated linear lookups amplify the large refreshes.** `Library.swatch`, `Library.definition`, and palette/name helpers scan arrays (`Model.swift:392,779; ColourProfiles.swift:127`). `fillPage` separately scans `lib.colours` twice per tile for dates (`StudioWindow.swift:2877`) and rebuilds a global palette-bar map even if bars are hidden (`StudioWindow.swift:2854-2855`). `WorkspaceFavourites.sync` searches old favourites for each new entry (`StudioWorkspace.swift:8-16`). The `Project Use Count` sort invokes full lineage presentation once per palette (`PaletteAssetHandler.swift:143-149`). Build immutable ID/key indexes once per library revision; compute only the mappings the active route needs. A copy-parent adjacency index makes use-count calculation linear in graph size rather than repeated global scans.

9. **P2 — Hidden/unchanged UI is still recomputed.** `refreshAnalysis` calls histogram, bloom, expanded panes and filmstrip update during page rebuild (`StudioWindow.swift:3188-3204`); `BloomWorkspace.update` reloads its table (`WorkspaceAnalysis.swift:516`). `WorkspaceCatalogues.update` constructs and sorts the full node forest before its same-nodes check decides whether `reloadData` is needed (`StudioWorkspace.swift:342-521`). Keep the existing identity-preserving reload suppression, but add revision/route guards *before* constructing trees and analysis datasets. Visible panels should subscribe only to the data they show.

10. **P2 — Startup creates the classic UI even for the Studio route.** `prepareMainWindow` constructs `MainWindowController` (`main.swift:313-318`), and its content controller eagerly constructs Palette, All Swatches, Lab, Contrast, Typography and Overview controllers (`MainWindow.swift:67-75`); `revealMainWindow` normally shows Studio (`main.swift:322-325`). The classic controller still owns menu commands and the `--classic` path, so it cannot simply be deleted. Migrate commands to an app-level router, then lazily create the classic window only when invoked. Measure launch-to-interactive before and after.

11. **P2 — Session persistence runs once a second even when unchanged.** `StudioWindowController.startSessionMemory` schedules a one-second timer (`StudioWindow.swift:37-42`). Each tick captures the layout, validates it and JSON-encodes it; only after encoding does `WorkspaceSession.write` compare with the previous bytes (`StudioWindow.swift:373-384; WorkspaceLayouts.swift:31-36`). The idle sample observed this call. Save on state/scroll changes with a debounce and retain the close/resign-key flush. This should remove needless main-thread work without risking restoration.

12. **P2 — External sidecars and previews need bounded loading and freshness.** `AssetNotes.record` synchronously reads/decodes a sidecar on first access; tile drawing queries it (`AssetNotes.swift:43-56; UIPrimitives/ViewportGrid.swift:447-450`). A network-backed image folder can stall scrolling. The static cache does not check file version after initial load. Image intake reads all adjacent JSON/XML/XMP/CSV/TSV sidecars without a file-size cap (`StudioWindow.swift:804-823`). Load notes asynchronously or prefetch with file-version stamps, and cap/stream untrusted sidecars before parse. Preserve visible error reporting instead of silently treating oversize/damaged data as empty.

## Good foundations to retain

The file manager has explicit identity/provenance checks, coordinated writes, recovery transactions and conflict protection. Thumbnail and image-source scanning already run off the main thread with generation guards. The grid draws only visible cards, the ICC conversion layer caches transforms with bounds, and the history model stores deltas rather than full snapshots. These are sound foundations; the main issue is that broad synchronous callers defeat their benefit.

## Production gate

1. Establish reproducible `os_signpost` intervals around `apply/mutate/load/write`, `reload/fillPage`, `refreshCardSettings`, tree construction, `Rendering.of`, image-batch updates and sync. Report p50/p95 main-thread time and allocations for 100/1k palettes, 30/300/3k swatches, 1k/10k images, with sync on/off and local/network storage. Include a warm-cache and cold-cache run.
2. Fix findings 1–6 before calling interaction speed production-ready; then verify every visible result (ratings, print changes, collection colour, import selection, metadata and history) remains correct after incremental updates. Compare file digests and recovery behaviour across crash/fault injection to ensure fast paths keep transaction guarantees.
3. Run the self-tests on the exact release source snapshot, then direct-download build/install/sign/notarization and Store archive checks separately. The current installed-binary self-test passing does not certify this dirty working tree. Add automated latency/memory regression tests rather than tests that only reproduce implementation details.
4. Run Instruments Time Profiler, Allocations and Points of Interest during a format-row toggle, typing search, one palette rating, opening a 30-swatch palette and a 10k-image intake. Track long main-thread stalls and retained thumbnails. A five- or twelve-second sample is too short to establish p95 responsiveness.

This review identifies code-backed costs and one observed session-timer stack; it does not claim measured user-visible milliseconds for each path. No source code was changed during the audit.

## Implementation follow-up — 20 October 2026

The subsequent performance pass changed the source and installed app build 357 (`06e4b29+`). The original findings above remain the audit baseline, not a description of the current implementation.

| Findings | Change |
|---|---|
| 1 | Mutations skip no-ops and return the written library without a second full read. Dirty palette IDs avoid serializing unchanged files. Portable rating, flag, tag, note and metadata edits write only their asset file; a version-checked library snapshot avoids decoding unchanged catalogues. Renames and structural edits still take the full coordinated transaction path. |
| 2–4 | Route and presentation changes use scoped refreshes. Search is debounced and an unchanged result retains the grid. Value rows format only visible cards, print proof is computed outside drawing, and review controls use lightweight snapshots with idempotent setters. |
| 5–6 | Image thumbnails use bounded caches and redraw their visible tile; intake previews batch updates. Print proof conversion moved to a bounded serial worker with generation invalidation. |
| 7–9 | Sync planning runs off the main thread and checks local disk again before applying. Palette IDs, colour dates, favourites, and use-count lineage have targeted indexes. Analysis datasets and library tree reloads are skipped when the relevant route or data is unchanged. |
| 10–12 | The classic window is created only when invoked. Workspace session saving is event-driven and debounced. Notes are loaded off the drawing path with file-version freshness and bounded sidecar size; intake sidecars are capped. |

An installed-app idle sample after the first build exposed a further hotspot outside the original twelve: the 15-second linked ICC availability timer called `space(for:)` on the main thread, re-reading and hashing every linked profile even when unchanged. The final build checks availability on a utility queue every 60 seconds, and cached transforms are reused while the file's inode, size and modification time match. A changed profile is hashed against its linked identity before use.

The final release-source self-test passed **1,391/1,391** and the exact installed bundle passed **1,401/1,401** (the bundle adds resource checks). The signed `/Applications/Colorgain.app` launched to the Studio window and displayed the 30-swatch Swiss Grotesque palette without the earlier row-overlap artifact. `codesign --verify --deep --strict` passed. The direct build is signed but has not been notarized in this local pass; the Store archive is a separate target and was not built here.

The opt-in self-test fixture (`COLORGAIN_BENCHMARK=1`) measured one run on this Mac: at 100 palettes, cold load **0.112 s**, rename **0.102 s**, review **0.057 s**; at 1,000 palettes, cold load **1.068 s**, rename **1.081 s**, review **0.465 s**. Before this pass, the 1,000-palette rename fixture took **3.489 s**. These are single-run wall times, not p95 UI latency. Full-tree renames and cold reads still scale with catalogue size; the production gate above still calls for Instruments sampling, larger datasets, and network-volume fault testing before claiming consistently sub-frame interactions.

## Sub-second follow-up — 20 October 2026

The catalogue path now reuses a validated inventory and decoded asset documents, checks a file-version snapshot before portable single-palette edits, and updates a rename's file and catalogue link without rewriting unrelated assets. Index unknown-field matching is indexed rather than quadratic. Asset inspection uses four bounded workers, validates each palette/typography document once, and maps the validated root's logical and physical path aliases without per-file symlink resolution. The existing recovery, identity, provenance, and external-change checks remain in place. Opt-in `COLORGAIN_PERF_TRACE=1` prints stage timings for further profiling; it is silent in normal use.

Three consecutive release-binary runs on this Mac with 3,000 local palettes measured catalogue load **0.931–0.945 s**, single-palette rename **0.499–0.509 s**, and review edit **0.248–0.251 s**. Each run passed **1,395/1,395** source self-tests. The installed `/Applications/Colorgain.app` passed **1,405/1,405** bundle self-tests, passed strict deep signature verification, and opened the Studio window with the 30-swatch Swiss Grotesque palette. Native Settings card-format toggles measured roughly **117–148 ms** per click in the earlier UI smoke test; grid/list and palette navigation were also below **160 ms** there. Those are action-specific local measurements, not a universal <1 s guarantee for arbitrarily large catalogues, network volumes, imports, or exports. The production gate above remains relevant for p95 and stress testing.

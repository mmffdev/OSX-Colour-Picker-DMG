# Panels and trees contract

`WorkspaceBranchTree.Row` owns horizontal tree padding for every panel. The reference is the 16 pt body inset in ordinary panels: connector circles begin at that left inset, node cards end at that right inset, and cards without connectors use the same outer margins. My Favourites uses the connector tree too.

Deleting a palette or colour removes its identity from every Collection in the same catalogue transaction; removing an imported reference clears its Collection entry as well. The Collections panel repairs older links to missing palettes when it opens. Palette Favourites come from surviving library assets and its portable records sync to that list.

Parent: [UI framework](c_ui_framework.md). `WorkspaceRail` owns a 360 pt dock, panel order, outer scrolling, drop targets and side-specific scrollbar. `WorkspacePanel(id:title:content:height:resizable:draggable:)` owns identity, collapse, drag, content sizing and optional 18 pt resize footer. A sole source panel uses `fillsRail`; no second inner scroll or resize grip appears. `WorkspacePanelContentMetrics` and `WorkspacePinnedPanelContent` supply content extent and pinned controls.

`WorkspacePanelHeader` is 40 pt and owns the gradient surface, disclosure, title, help and actions. Its title and open-stroke disclosure chevron centre on the header line; the back control uses the same chevron stroke. `WorkspaceSectionHeader` uses the same 40 pt height, centred title and chevron, but is flat; it owns subdivisions inside Library and Import. Its optional preference key persists expansion, while a transient section omits the key. Tree headers do not carry a colour icon. The **Multi Colour Select** node context action opens a persistent picker in the centre viewport; this action is available on editable Workspace, project, My Library and Collections nodes, but not My Favourites. Keep the shared 40 pt header height.

Designer → Palette's Image Palette RailInfo panel omits the back/close chevron while its page hides Rail1. Other RailInfo panels retain their close action.

Workspace asset-bucket context Import actions use `BucketIntakeInfoPane` inside the existing RailInfo `WorkspacePanel`. Its destination stays fixed to the clicked bucket or My Library category, while source files, Copy/Move/Reference and confirmation live in the rail. Opening it does not navigate to the Import viewport.

`WorkspaceBranchTree` renders all Library and Import hierarchies. Standard rows are 34 pt and palette rows are 64 pt; depth advances 14 pt, and rings/connector paths are shared. Tree row spacing is 2 pt, surface inset 3 pt and section edge padding 3 pt. Adjacent rounded cards have an 8 pt visible gap (3 + 2 + 3); do not add another spacer. Palette content uses two 28 pt lines within a 64 pt row, centred with 4 pt above and below. Leaf icons and right-aligned counts sit 8 pt inside the side edges. The Workspace panel's subsections retain the shared 16 pt footer padding. Configure `swatchFamily` as `.drives`, `.charcoal` or `.yellow`, or `swatchFamilyForItem` for mixed destination trees. Each family has ten steps, darkest/fullest at root and lighter at depth. From-drive trees use `#1F2933` at level 1. Catalogue To and My Library trees use neutral charcoal by default; yellow remains available as an explicit destination family. `rowColour`/`rowInk` allow explicit saved node colours to override depth hues across projections. Never reorder a projection differently from the source tree without an explicit ordering prop.

Disclosure chevrons derive their ink from the current tree row, including at first paint and after theme changes. Refreshing a row redraws its chevron with the same ink as its label; a recycled disclosure must not retain another row's colour.

In Multi Colour Select, a selected tree row grows 4 pt while its node card keeps its normal size. A shared 2 pt black-and-white diagonal band sits 2 pt farther from the card than before, leaving the card's editable border visible. Picker previews and swatch markers resolve the row's live background, text and border, including depth colours and older nodes with no saved override. The Current selection pseudo-node stays unwrapped; clicked saved designs retain their target band. No seeding pass is needed.

Each seeded schema child uses the owning project UUID plus its schema node UUID as its appearance key. Project roots already carry their own UUID. The Library tree and Import destination projection use the same scoped child key; an old appearance saved under the shared schema UUID is copied once to each scoped key before future edits diverge.

The Import Destination tree is a projection of the source schema: Palettes exposes the actual palette bucket and its ancestors, hiding unrelated asset siblings; My Library exposes a Palettes child. ASE keeps its container targets because it can create an ASE bucket on confirmation. The Custom Folders branch follows those catalogue branches. It opens Common Folders, Internal Drives, External Drives and Network Drives by default, then loads subfolders asynchronously on disclosure using the same `WorkspaceBranchTree` renderer and drive swatch family. Copy and Move write to the selected physical folder and track the external path in the active catalogue. Reference requires a catalogue or My Library destination because it writes no file into a disk folder. File Handling and File Renaming are separate `WorkspacePanel` instances above Destination; their form selectors use the house `AnalysisMenu`/`SwissDropdown.MenuPanel` contract. Renaming uses a sequence suffix and preserves the source extension. `WorkspaceImportMethodButton` uses a raised neutral surface in dark appearance, black ink on selected house yellow, and the same border/split geometry in both appearances. A file import runs off the main thread with a visible `SwissFocusModal` progress bar; success refreshes the source selection and destination tree.

The Library-side **Collections** panel is a separate `WorkspacePanel` with its own `WorkspaceBranchTree`: root Collections, fixed `+ Add Collection` trigger, unlimited user Collection nodes, then linked asset nodes. New `.colcat` catalogues seed `My Collection`; older catalogues without the field seed it on first load. An explicit empty list stays empty. The connector overlay sits above the tree so branch curves and rings stay visible. Each Collection row uses the shared circle connectors, reorder grip before its icon, optional editable swatch fill with contrast-aware text (an unset colour leaves a neutral outline), and a tightly grouped sliders Edit action immediately before the right-aligned count, without the general tree action gap. Every linked asset row has a clear surface and, only when its parent Collection has a colour, a rounded 5 pt leading border; its text uses the normal theme ink. Add/Edit use `SwissFocusModal` with name and colour field, opening `StudioColourPicker` with Select/double-click to commit the modal draft before Save. Linked native and imported palettes use the shared 64 pt two-line [lowestnode](c_c_ui_lowestnode.md) layout. A Collection can contain any asset type and the same asset key can appear in several Collections. The Import-side **Add to Collection** panel uses `SwissCheckbox` plus `AnalysisMenu`, sits above Destination, and offers header `+` for creation. Membership lives in `CatalogueFile.assetCollections` in `.colcat`; it never changes the ownership/schema tree.

`WorkspaceBranchTree.Cell` aligns trailing actions and counts independently of depth; indent moves only the leading symbol and label. Every navigational node shows an aggregate child count, including zero. Assets sums all descendant assets; Information shows `(0)` when empty.

Selecting a folder in any Library-side tree or the Collections tree opens its descendant assets in Viewport-Page. The tree builds ordered sections from each immediate parent that directly holds assets, so a higher node shows Palettes, Typography and other asset groups under their own headings; selecting a single bucket shows that bucket's cards. Collection root groups cards by Collection. `TileGrid.sections` lays out each heading across the full grid width, starts the next group's cards on a new row, and preserves ordinary card selection, controls and grid/list modes. Navigating to another page clears the tree bucket scope.

`AssetMetadataPanel` is content-sized. Changing between no selection and a selected asset must ask its owning `WorkspaceRail` to arrange again, so the six-row inspector never overlaps the next panel and the empty state never retains the inspector's height. A single selected palette takes priority; with no selection, the palette still being analysed in Rail2 supplies the metadata subject. Multiple selection remains empty. The empty state keeps the inspector preset and Metadata Settings available.

Current navigation rows in the client and My Library trees put a gear immediately before the count at every depth. The gear opens the same house menu as right-click. Non-asset menus start with Multi Colour Select, followed by Colour; both open the shared viewport picker on the menu's source node even if it was not selected. Favourites remain outside Multi Colour Select. `WorkspaceColourMode` keeps `WorkspaceColourPickerPage` in Viewport-Page while tree clicks become target selection. Plain click replaces, Command toggles, and Shift extends a range; Command also preserves selections in other editable trees. The picker has independently enabled Background, Text and Border palettes, laid out in that order with equal outer and between-block spacing, each with square hue/grey swatches at 75% of the former width and a No Colour reset above the final hue column. Hue-name headings are omitted. Grayscale rows share the hue grid's right edge. Every matching selected colour is outlined, including mixed selections; colours outside the fixed grid appear as exact Current swatches above it. A saved, unlimited Custom Colours grid sits below the Background palette, aligned to its left edge. A house rule separates it from the three channel palettes and spans precisely from the first palette's left edge to the last palette's right edge. Its two eyedroppers sit together below the first swatch: the plain icon samples once, while the plus-badged icon repeats after each successful screen sample until cancelled. Both sample across displays. Right-clicking a channel swatch offers Add To Custom Palette. Palette and swatch halos and right-click menus place Add To Custom Colours directly below Add To Collection; they copy the current hex values, including every colour in a palette or multi-selection, without retaining an asset link. Custom is one colour bucket with no channel tabs. Plain-clicking one of its swatches opens Background, Text and Border apply choices. Shift-click extends the selection and Command-click toggles swatches without applying them; right-clicking a selected swatch offers to remove the whole selection, while right-clicking an unselected swatch targets that swatch alone. Below Custom Colours, **My Designs** shows a live pseudo node for the first selected target and a Save As Design action. Its previews use the tree’s 34 pt row and 28 pt rounded leaf surface at the same 260 pt width; saved design labels sit above them without an outer card border. Named designs persist without a count limit in app preferences and form a wrapping grid; clicking a leaf applies its saved Background, Text and Border together to every selected tree node, including No Colour values. Clicking the label edits it inline; adjacent Rename and Delete icons edit or remove that saved design, while right-click offers the same actions. Custom Colours places its samplers under the first swatch columns and sizes its height to the swatch rows and samplers, with no blank spacer. The lower area scrolls as designs accumulate. A swatch applies once to the selected nodes and retains the selection so another channel can be set next. Border colours are saved in `WorkspaceNodeAppearance` with background/text overrides and stroke the node card across filled, clear and outlined tree rows. A new plain node click replaces the targets without applying the previous colour; swatches never remain active as brushes. The viewport title and tab temporarily read Choose node colours; the global Actionbar, VP-Actionbar, VP-Footer and the tab's right-side controls hide during the session. Escape or Done ends the session and restores ordinary navigation and chrome. Explicit node colours override asset accent strips; uncoloured asset rows keep their clear surface and Collection accent. Repainting colour does not rebuild tree geometry.

Simple lists that do not need connector lanes use `WorkspaceOutline`. `StudioRail`/`AreaHeader` remain fixed-rail adapters; avoid introducing new fixed rails when a docked `WorkspacePanel` can express the content.

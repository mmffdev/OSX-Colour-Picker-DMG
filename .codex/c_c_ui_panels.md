# Panels and trees contract

Parent: [UI framework](c_ui_framework.md). `WorkspaceRail` owns a 360 pt dock, panel order, outer scrolling, drop targets and side-specific scrollbar. `WorkspacePanel(id:title:content:height:resizable:draggable:)` owns identity, collapse, drag, content sizing and optional 18 pt resize footer. A sole source panel uses `fillsRail`; no second inner scroll or resize grip appears. `WorkspacePanelContentMetrics` and `WorkspacePinnedPanelContent` supply content extent and pinned controls.

`WorkspacePanelHeader` is 34 pt and owns the gradient surface, disclosure, title, help and actions. `WorkspaceSectionHeader` is also 34 pt but flat; it owns subdivisions inside Library and Import. Its optional preference key persists expansion, while a transient section omits the key. Change its props when a subsection needs a new action, trailing control or help variant. Do not create a second header at a different height.

`WorkspaceBranchTree` renders all Library and Import hierarchies. Standard rows are 34 pt, depth advances 14 pt, and rings/connector paths are shared. Configure `swatchFamily` as `.drives`, `.charcoal` or `.yellow`, or `swatchFamilyForItem` for mixed destination trees. Each family has ten steps, darkest/fullest at root and lighter at depth. From-drive trees use `#1F2933` at level 1. Catalogue To trees use `#242424`; My Library uses `#F4BE00`. `rowColour`/`rowInk` allow explicit saved node colours to override depth hues across projections. Never reorder a projection differently from the source tree without an explicit ordering prop.

The Import Destination tree is a projection of the source schema: Palettes exposes the actual palette bucket and its ancestors, hiding unrelated asset siblings; My Library exposes a Palettes child. ASE keeps its container targets because it can create an ASE bucket on confirmation. The Custom Folders branch follows those catalogue branches. It opens Common Folders, Internal Drives, External Drives and Network Drives by default, then loads subfolders asynchronously on disclosure using the same `WorkspaceBranchTree` renderer and drive swatch family. Copy and Move write to the selected physical folder and track the external path in the active catalogue. Reference requires a catalogue or My Library destination because it writes no file into a disk folder. File Handling and File Renaming are separate `WorkspacePanel` instances above Destination; their form selectors use the house `AnalysisMenu`/`SwissDropdown.MenuPanel` contract. Renaming uses a sequence suffix and preserves the source extension. `WorkspaceImportMethodButton` uses a raised neutral surface in dark appearance, black ink on selected house yellow, and the same border/split geometry in both appearances. A file import runs off the main thread with a visible `SwissFocusModal` progress bar; success refreshes the source selection and destination tree.

The Library-side **Collections** panel is a separate `WorkspacePanel` with its own `WorkspaceBranchTree`: root Collections, fixed `+ Add Collection` trigger, unlimited user Collection nodes, then linked asset nodes. New `.colcat` catalogues seed `My Collection`; older catalogues without the field seed it on first load. An explicit empty list stays empty. The connector overlay sits above the tree so branch curves and rings stay visible. Each Collection row uses the shared circle connectors, reorder grip before its icon, editable swatch fill with contrast-aware text, and a tightly grouped sliders Edit action immediately before the right-aligned count, without the general tree action gap. Every linked asset row has a clear surface and rounded 5 pt leading border in its parent Collection colour; its text uses the normal theme ink. Add/Edit use `SwissFocusModal` with name and colour field, opening `StudioColourPicker` with Select/double-click to commit the modal draft before Save. Linked native palettes use the exact shared 56 pt two-line palette tree cell, including spectrum/count above favourite, target, rating and flag; imported palette files use its two-line preview. A Collection can contain any asset type and the same asset key can appear in several Collections. The Import-side **Add to Collection** panel uses `SwissCheckbox` plus `AnalysisMenu`, sits above Destination, and offers header `+` for creation. Membership lives in `CatalogueFile.assetCollections` in `.colcat`; it never changes the ownership/schema tree.

`WorkspaceBranchTree.Cell` aligns trailing actions and counts independently of depth; indent moves only the leading symbol and label. Every navigational node shows an aggregate child count, including zero. Assets sums all descendant assets; Information shows `(0)` when empty.

Current navigation rows in the client and My Library trees put a gear immediately before the count at every depth. The gear opens the same house menu as right-click. Non-asset menus start with Colour and its swatch, followed by a divider; the custom picker commits a chosen swatch immediately. Asset menus have no independent colour assignment. Asset rows have a clear surface and standard dark outline. A palette or other linked asset shows the first containing Collection's colour only as its rounded 5 pt left border in every tree where it appears; when it belongs to no Collection, it has no Collection border. Repainting colour does not rebuild the tree or change its geometry.

Simple lists that do not need connector lanes use `WorkspaceOutline`. `StudioRail`/`AreaHeader` remain fixed-rail adapters; avoid introducing new fixed rails when a docked `WorkspacePanel` can express the content.

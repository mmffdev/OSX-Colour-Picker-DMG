# Asset grid, card and swatch contract

While Designer is active, an image dropped anywhere in its window selects Palette and starts or replaces the twin-image comparison. File URLs, image pasteboard data and image URLs enter a transient in-memory session; none create a Library record. A replacement starts a fresh image palette recipe and clears the previous sample targets and swatches only after its new image decodes successfully. The existing source chooser and Import from Disk retain their own explicit Library-reference workflow.

Parent: [UI framework](c_ui_framework.md). `StudioPage` supplies the scrollable viewport and `AssetPageProps` controls renderer, pagination, menus and filters. `TileGrid` owns columns, card frames, scrolling, selection, keyboard/mouse multiselect and item callbacks. Feed new import types `TileGrid.Item` values; extend a renderer prop when preview content differs. Never create a route-local grid or selection engine.

`TileGrid` uses a 48 pt column gap and an extra 32 pt horizontal inset inside the page's 16 pt margins, so grid cards have 48 pt at both outside edges. List rows and all vertical geometry retain their existing spacing. The grid has a 140 pt visual block (five 28 pt units), a 56 pt word area (two units), and responsive card widths. Palette cards show colour bands, title and review/status data; swatch cards show one colour plus value/proof information. Palette files in Import set `importPaletteCards` and share the framed Library palette geometry, adding a 16 pt selection checkbox in the header. All Import cards omit notes, halo and the bottom notch; their row gap is 24 pt. Library cards retain those actions. Other import candidates show a preview or file glyph and a checkbox over the preview. Images may use a thumbnail and expanded view. Selecting a From folder scans files immediately, independently of the tree's child-folder loading; re-entering Import rescans the retained selection even when the asset type has not changed.

Card value rows are formatted only when visible, using a stable 280 pt value-column minimum and a bounded text cache. Palette review controls receive lightweight name/review snapshots. Print predictions run outside drawing on a serial worker, keyed by asset identity and invalidated when library or output settings change. Image cards request visible thumbnails through `onImagePreview`; the caller owns a bounded, file-versioned cache. A search whose resulting item identities are unchanged retains the grid's controls and proof cache.

`PaletteReviewControls` is 124 pt wide (five 20 pt stars and a trailing flag). `PalettePageControls` uses a 184 pt base width plus optional Back. `PaletteFilterControls` is a 32 pt high VP-Actionbar capability. These live in `UIPrimitives/PaletteAssetControls.swift`. `SwatchListView` and `SwatchRow` live in `UIPrimitives/SwatchList.swift`; `ColourCard` remains a composed palette-editor view. Keep their data and visual behaviour aligned with the same palette/swatch asset semantics.

All owned asset cards and rows expose an Add To Collection action in their halo or context menu. Its immediate child actions are the available user Collections, with a check for existing membership; no member/owner move occurs. Multi-selected palettes and colours add/remove together. `AssetCollectionItem` stores stable kind/identity and a display-name fallback; `WorkspaceCollectionsPane` resolves live names when rebuilding. Import cards intentionally omit the halo because their Collection choice lives in the Import option panel.

Palette halo and context menus also open **Transform**. `WorkspaceTransformPage` displays a saved derivation graph in the clipped Viewport-Page, with palettes in successive columns. The gutter repeats a fixed-width [branch button | 252 × 155 transform panel] unit. A branch adds an empty full-height palette row; its connector trunk leaves the bottom of the first branch button. The panel selects a formula and adjusts its value live. Hue Rotation uses a half dial at the panel's left edge; 5° ticks and 45° major markers rotate beneath a fixed 90° clockwise measure point; dragging, its degree field and wheel input all work in 1° increments. The immediate right palette always previews. Each active panel has a Preview Downstream checkbox, on by default; when off, later palettes hold still during input and recompute on release or after wheel input pauses. Preview stays in memory and one settled value is saved. Each formula occupies the same panel footprint so future engines can replace its contents. After an active panel, the connector's + inserts another transform unit before the output palette; units expand the gutter by X, 2X, 3X as needed. Canvas, branch, transform and palette each have their own Swiss right-click menu. Transform headers use house yellow with dark ink; palette headers use dark ink with light text. Header double-click centres its node and restores 100% zoom. A mouse wheel zooms the canvas, while trackpad scroll pans and Hue-panel wheel input adjusts degrees. Connector gaps share one 24 pt unit on every side of the centred + button. A transform can Bypass its formula (with an ink wire around the panel and red crosses at both ends), Hide in place while reconnecting colours, or Delete with dependent outputs. Hiding a branch prunes its output and child branches; hiding a palette keeps the downstream chain. Transform and palette cards have equal 252 × 155 frames and use the shared card action tab. Palette spectra take the enlarged card body, while its tab opens a Save To selector for My Library or any unlocked project. The bypass glyph is traced in `assets/glyphs/transform-bypass.svg` and rendered natively. Delete needs no confirmation; deleting the source card discards this canvas graph and returns to Library. Saved Library palettes stay independent. Existing graphs without explicit branch slots migrate from their saved parent/child links. Empty-space drag pans, scrolling moves the viewport, and Command-scroll or pinch zooms about the pointer. Generated palettes remain graph snapshots in `CatalogueFile.paletteTransformGraphs` until a result is explicitly saved to Library. The source's original colour keys and full colour definitions are retained in the root snapshot for provenance.

Transform colour calculations use `ColourDefinition`/XYZ `Double` masters through the graph; 8-bit sRGB hex is only a card preview or explicit output. `PaletteTransformGraph.Formula` groups perceptual, tonal, palette, output/viewing, cinema/VFX and measured-colour engines. Every transform panel's preset icon opens a type-aware RailInfo editor. Parameters and portable `.coltra` presets are kept at full precision; the `.coldata` index (or optional catalogue `.colcat` index) is read for listing, and the preset file loads only when selected. The Transform page's 58 pt VP-Actionbar has Diagram Presets, Fit, zoom and Done icons. Diagram Presets opens RailInfo for a portable `.colnode` flow containing branches, transforms, settings and embedded LUT data; applying it replaces the source colours with those of the selected palette.

All component variants, source paths and dimensions are browsable in [the HTML catalogue](../design/ui-primitives-catalogue/index.html). Add an entry or update an existing one when a shared asset primitive changes.

Fonts have a primary header route and use the same `StudioPage` and `TileGrid` as other Library assets. On startup, My Library → Fonts enumerates available macOS families through `NSFontManager` with no folder scan or access prompt; the list refreshes on app activation. Installed families and imported fonts become 64 pt lowestnodes in Rail1, using the palette row's favourite, review, flag, tag and settings controls; their specimen name is typeset in the family and the spectrum position stays blank. Collection membership supplies the same left colour border. Dragging a font node to a product Fonts bucket stores a family reference, without moving the system font file. The viewport tab names the selected family. `FontSpecimenPage` aligns to the left and edits specimen words directly inside its ink/paper canvas; preset strings replace that text. Its family dropdown uses the shared house menu with favourite stars, expandable faces and live type samples. Weight and size use the image-palette extraction slider design. Metadata text inputs use transparent surfaces and a single rule. Back, Import, Add To Collection and Save actions belong to the VP-Actionbar. Save retains preview settings plus tags, keywords and notes. A font may join an asset Collection without moving its file; Colorgain mirrors font membership into a named user-visible Font Book collection. Import Fonts uses the shared destination tree and records copied fonts in My Library or a selected product bucket.
The Fonts viewport defaults to List, retaining its own Grid/List choice when the user switches routes. Each 96 pt font row puts its editable specimen words below the family name and above installation status, beside the existing `Aa` preview. Font specimen Bold and Italic choose a matching face where available and render a synthetic preview where a family lacks one. Apple Braille faces show a supported glyph exemplar when the user's Latin sample has no glyphs, while leaving the editable source text intact.
Font grid cards use the same 12 pt inset on all four sides. The family name and the format pill with its source label sit inside the card frame, share one left edge, and have a final 12 pt inset below the status row.
Font cards and list rows put a bottom-right Info action inside the asset frame. Entering Fonts opens RailInfo for the first visible family, or the last family explicitly inspected if it is present. The inspected font identity and Fonts Grid/List choice persist across launches. The detail page and RailInfo show read-only face facts from Core Text and the font's OS/2 table, including available language tags, detected script coverage, identifiers, licensing text, embedding flags, format, and glyph count; unavailable facts stay unclaimed. The multilingual character preview uses glyphs covered by the selected face.
Client Fonts buckets use those same font rows. Scoped bucket and Collection grids resolve font assets to family/specimen entries instead of generic imported-file cards; selecting one opens its font specimen page.
Font import candidates preview the quick-brown-fox specimen directly from each source file without registering it. Their light card rule and selection checkbox make the preview legible before import; no generic document placeholder or heavy selected border replaces the specimen.
The Fonts VP-Actionbar is plain, keeps Import on the left, and groups Format, sort and metadata filters on the right as in Palettes. Format choices distinguish OTF, TTF, TTC, OTC and system families with colour-outlined pills in the selector and on each row. All Formats defaults to Group By Type, with font-specific name ordering available beside it. The specimen tile reads "Colorgain" in its own typeface, fitted within the tile. Imported rows name their source file so same-family files remain identifiable, with the full stored path on hover. Font rows support right-click Collection and bulk Tags actions, plus dragging their font identity onto a product Fonts node.

The lower asset carousel is route-aware. Palette nodes show palettes, My Library and client Fonts buckets show their own font specimens, and photograph/image nodes show image thumbnails; routes without a single asset type do not reserve carousel height. Empty client Fonts buckets still open with a zero-count carousel. Selecting an entry opens that asset in the current viewport. The regular footer remains independent of the asset carousel.

Designer → Palette keeps the source photograph referenced in My Library → Photographs. When Original Reference is empty, its black-and-white barberpole encloses a two-column source chooser inset 40 pt: Import from Disk and My Library/catalogue Photographs and Images locations in the shared `WorkspaceBranchTree` on the left, including empty `(0)` nodes, and the shared `TileGrid` image cards on the right. Choosing an existing record opens its reference without importing a duplicate. The adjusted preview retains the yellow barberpole until it has an image. The Palette route hides Rail1 and Rail2 and opens RailInfo by default; its controls stay visible but disabled until an image loads, and its old import section is removed. Change Image below the original requires a second Confirm press, warns that current grade and extraction settings will clear, then resets those settings, reopens the chooser and disables RailInfo controls. ImageIO accepts JPG/JPEG, PNG, GIF (first frame), TIFF, HEIC/HEIF and supported RAW formats including ProRAW DNG through macOS decoders. Core Image produces an adjusted preview without touching the file; `DesignerPaletteExtraction.swift` supports perceptual clusters, dominant areas, vibrant accents, hue spectrum and light-to-dark selection. RailInfo displays saved recipes, all seven compact grade sliders, extraction menus and six compact extraction sliders, then output name/destination together; individual and Reset All controls preserve the source reference. The sliders use flat ink tracks and handles in both themes. The viewport has equally tall full-size original and adjusted previews as side-by-side pages with shared left title tabs and a 58 pt plain VP-Actionbar containing Save Recipe and Export Palette, with a bottom `WorkspacePanel` for hue-ordered extracted swatches. Export Palette writes those same ordered full-precision definitions first in My Library or an unlocked project palette bin. Save Recipe asks for a name, writes a settings-only `.colimg` under `workspace/Presets/Images`, and updates the `colorgain.coldata` index. Loading applies settings to the image currently open. Older image `.coltrans` recipes import their settings without retaining image links. `.coltra` and `.colnode` transform presets use `workspace/Presets/Transforms`.

The Adjusted pane's leading divider continues through its tab. A square control at the top left expands Adjusted over Original and reverses to restore the split. The comparison frame omits its redundant left and bottom rules; the Generated Palette area owns the single rule above the swatches. Point and area sampler tools are separate theme-ink outlined squares without a backing strip. Dragging an active target updates its linked swatch live from the exact centre pixel of the graded image; only the area tool averages a neighbourhood. The Reset button restores settings-derived target positions and colours.
The full-width control appears only after the adjusted image loads. The source chooser opens without a selected location; its selectable parent nodes show their Photographs and Images children as drill-down actions, and choosing a leaf shows its image cards.
The control overlays the pane margin; Original and Adjusted use the same image-area geometry, so toggling or showing the control never shifts the adjusted image vertically.
